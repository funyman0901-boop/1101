ГАБАРИТЫ ДЕТАЛЕЙ — КОМПАС-3D v24
Windows x64, отдельная утилита. Python устанавливать не требуется.

ВЕРСИЯ 1.5 — ОБРАБОТКА ПАПКИ

ЗАПУСК
1. Распакуйте архив и запустите KompasDimensions24.exe.
2. Нажмите «Выбрать папку...» и укажите папку с файлами .m3d.
   Можно также вставить полный путь в поле вручную.
3. Оставьте способ «Габариты готовой модели».
4. Нажмите «Записать свойства + Excel» для добавления свойств в файлы.
   Кнопка «Сформировать Excel» выполняет только измерение, без записи.

Открытая сборка не требуется. Утилита подключается к запущенному КОМПАС-3D
или пытается запустить установленный КОМПАС автоматически. Требуется
установленный КОМПАС-3D v24. Файлы .a3d не обрабатываются.
Вложенные папки просматриваются автоматически. Расширение .M3D также
учитывается. Каждый найденный файл обрабатывается отдельно.
Перед записью закройте отдельные окна деталей и сохраните изменения.
При нескольких экземплярах КОМПАС оставьте один нужной версии.
Первую запись выполните на копии папки с деталями.

ВЕДОМОСТЬ ИЗДЕЛИЯ ПО СБОРКЕ
В архиве есть Пример_ведомости.xlsx с демонстрационными данными.
1. Нажмите «Ведомость по сборке .a3d...» в основном окне.
2. Выберите существующий файл сборки. Сборку не обязательно открывать вручную.
3. Дождитесь обработки. Ведомость откроется в отдельном окне просмотра.
4. Кнопка «Открыть Excel» откроет сохранённую однолистовую ведомость.
Папка моделей для этой кнопки не нужна. Папка отчётов используется та же,
которая указана в основном окне. Сборка и детали не сохраняются.
Если выбранная сборка уже открыта, сначала сохраните в ней изменения.
Закройте отдельные окна исходных деталей перед формированием ведомости.

Количество берётся из всех вставок текущего исполнения выбранной сборки,
включая копии и повторные вложенные сборки. Альтернативные исполнения,
которые не вставлены в изделие, не учитываются. Исключённые из расчёта
компоненты не включаются. Невидимость сама по себе не является исключением.
Покупная подсборка, отнесённая к «Стандартным» или «Прочим изделиям»,
считается одной штукой, без включения её внутренностей второй раз.

Все разделы находятся на одном листе «Ведомость». Колонки: №, сортамент,
длина (мм), площадь (м²), количество (шт.).
- Сортамент: профили, трубы, уголки, прутки, брус, доска и другие явно
  распознаваемые линейные материалы. Одинаковые полные названия материала
  объединяются, длины каждой вставки суммируются. Колонка количества пуста.
  Например: 4 трубы по 1000 мм дают 4000 мм.
- Пиломатериалы: одинаковый материал, порода, сорт, ГОСТ и сечение
  объединяются по суммарной длине в мм. Доски разной длины считаются вместе,
  но разные сечения и разные породы древесины не смешиваются.
  В тройке размеров материала (50х150х6000) длина исключается из ключа
  группировки, сохраняется сечение. Сечение берётся по двум меньшим габаритам.
- Листы: одинаковый материал и толщина объединяются по суммарной площади.
  Разные длины и ширины заготовок складываются; разные толщины раздельно.
  Площадь (м²) = сумма(длина мм * ширина мм * количество) / 1000000.
  Колонки длины и количества для листов пусты. Площадь выводится числом,
  без формул, с точностью до 8 знаков после запятой. Толщина — меньший габарит.
  Тройки размеров листа в названии материала нормализуются до толщины.
  Площадь относится к прямоугольной габаритной заготовке: вырезы и отверстия
  не вычитаются. Автоматическая развёртка гнутых листов не выполняется.
- Метизы: компоненты с признаком стандартного изделия либо разделом
  «Стандартные изделия». Группируются по полному названию и обозначению.
- Прочие изделия: явно назначенный раздел «Прочие изделия», количество в шт.
- Без материала / не распределено: в конце, включая нераспознанный сортамент.

Материал читается из свойства Material вставки с учётом данных источника.
Для каждого вставленного исполнения размеры определяются по соответствующему
исполнению исходного файла .m3d; поворот вставки не увеличивает габариты.
Используется выбранный в основном окне способ измерения.
Распознавание вида материала выполняется по словам «труба», «лист», «брус»
и т.п. Само по себе название «Сталь 3» не определяет сортамент: оно будет
в конце списка. Разные марки стали и ГОСТ в названии не объединяются.
Нормализуются регистр, пробелы и символы х/×/x между размерами.

Гнутые листы не разворачиваются: длина, ширина и толщина выводятся по
осевому габариту готовой модели. Для таких деталей требуется отдельно
подготовленная геометрия/параметры заготовки. Локальные детали без .m3d,
ошибки открытия и неоднозначные исполнения отмечаются в журнале.
При ошибках отчёт помечается как «НЕПОЛНЫЙ ОТЧЁТ»; перед использованием
устраните ошибки. Неизвестные данные не подменяются нулевыми длинами.

В папке Ведомость_дата_время сохраняются:
- Ведомость.xlsx — один лист, только значения без формул;
- Ведомость.json — строки и состав каждой группы;
- Журнал.json — ошибки и исключения.

РЕЗУЛЬТАТЫ ЗАМЕРА ПАПКИ
По умолчанию: папка «Габариты КОМПАС» в пользовательских «Документах».
Для каждого запуска создаётся отдельная папка:
- dimensions.xlsx: габариты, журнал и итоги;
- journal.json и processing.json: журнал;
- backups: исходные файлы перед записью свойств.
Кнопка «Открыть отчёты» открывает папку результатов.
Excel содержит значения без формул. Размеры — числа в миллиметрах,
округление до 0,001 мм, порядок: длина >= ширина >= высота.
Обозначения деталей не изменяются.

ИСКЛЮЧЕНИЯ ПРИ ЗАПИСИ ГАБАРИТОВ
Если раздел спецификации не задан, файл считается обычной деталью.
Исправлен ответ КОМПАС (False, None, False) для незаданного раздела.
Другие ошибки чтения не игнорируются.
Исключаются IPart7.Standard и разделы спецификации
«Стандартные изделия» / «Прочие изделия». Имена файлов не используются
для определения категорий. Категория читается из самого файла детали.
Исключённые файлы открываются для проверки категории, но размеры и свойства
в них не изменяются, файл не сохраняется.
Папка отчётов, её резервные копии и общий источник определений исключены
из поиска. Ссылки и точки повторного анализа каталогов не обходятся.
Ошибка одного файла не останавливает остальные. Ошибки чтения папок
фиксируются отдельно. В журнале отображается прогресс [номер/всего].

СПОСОБЫ ИЗМЕРЕНИЯ
1. Габариты готовой модели: GetGabarit(False, False) в исходном .m3d.
   Поворот геометрии внутри исходного файла может увеличить габариты.
   Это осевой габарит, а не минимальный ориентированный параллелепипед.
2. Размеры заготовки: значения переменных BLANK_L, BLANK_W, BLANK_H.
   Переменные должны хранить размеры в мм; их можно связать с длиной
   выдавливания и размерами эскиза. В результат копируются вычисленные числа.
   Автоматическое распознавание произвольного эскиза не реализовано.
   Если переменных нет, деталь отмечается ошибкой, без подмены габаритами.

ОБЩИЕ ОПРЕДЕЛЕНИЯ СВОЙСТВ
При первой записи создаются три числовых определения:
«Длина», «Ширина», «Высота». Числа трактуются в миллиметрах.
Общий источник хранится в:
%LOCALAPPDATA%\KompasDimensions\properties
В папке dimensions_seed.m3d и properties.json. Не удаляйте и не пересоздавайте
её после начала использования: файлы обеспечивают общие ID свойств.
Для нескольких рабочих мест перенесите эту папку с первого компьютера
до первого запуска записи на остальных компьютерах.
Чтобы включить размеры в стандартный отчёт КОМПАС, добавьте эти определения
в список свойств отчёта через «Управление свойствами», используя
dimensions_seed.m3d как источник. Для вставок должно использоваться
значение свойства из источника, без переопределений.
При существующем одноимённом свойстве с другим ID программа фиксирует
конфликт и не заменяет его.

ОБРАБОТКА ИСПОЛНЕНИЙ
Для каждого исполнения выбирается его геометрия, выполняется перестроение
и измерение. Значения записываются через IPropertyKeeper этого IEmbodiment.
В Excel и журнал добавлена колонка «Исполнение» с обозначением исполнения.
Признак стандартного компонента и раздел спецификации проверяются отдельно.

До записи измеряются все подходящие исполнения. Резервная копия создаётся
один раз на исходный файл. Затем записываются значения всех исполнений,
проверяется, что соседние исполнения не перезаписаны и размеры исключённых
исполнений не изменились по наследованию. Если обнаружена ошибка одного
исполнения, весь файл остаётся без сохранения, обработка других файлов
продолжается. Если значения распространяются на исключённое исполнение
по наследованию, файл не сохраняется и конфликт фиксируется в журнале.
Перед сохранением восстанавливается исходное активное исполнение.
Файл сохраняется один раз; после открытия с диска проверяются значения
каждого обработанного исполнения. При ошибке проверки после Save используйте
резервную копию: файл уже мог быть изменён.

ИСПРАВЛЕНИЕ UPDATE
Убран обязательный IPart7.Update() у верхнего компонента после записи
свойств. Этот вызов возвращал False, несмотря на успешную запись значений.
Контроль SetPropertyValue, чтение чисел и проверка после Save сохранены.

ОГРАНИЧЕНИЯ
Все исполнения файла обрабатываются отдельно, включая основное. Используется геометрия исходного файла,
а не результат сборочных операций. Сборки не открываются и не сохраняются.
При ошибке после Save файл уже может быть изменён: для восстановления
используйте резервную копию из backups, закрыв документ в КОМПАС.

ПРОВЕРКА СБОРКИ
Программа версии 1.5 собрана PyInstaller под Windows x64 через Wine.
Пройдены 49 тестов: вложенные папки, исключения, ошибки отдельных файлов,
резервные копии и контроль сохранения на имитации COM.
Проверены запуск окна и экспорт Excel из упакованного .exe.
КОМПАС-3D в среде сборки отсутствует: реальное подключение COM, измерение
и сохранение .m3d на установленном КОМПАС v24 ещё не проверены.
Диагностика приложения:
%LOCALAPPDATA%\KompasDimensions\last_error.txt
%LOCALAPPDATA%\KompasDimensions\startup_error.txt

Исходный код и команда повторной сборки находятся в папке source.
